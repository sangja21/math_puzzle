# 신규 9단원 라우팅·카테고리 검토

함수~적분 9단원이 사이트에 추가될 때, *URL 구조 / 카테고리 / 사이드바 그룹*
을 어떻게 가져갈지 옵션을 정리하고 비교. **결정은 사용자 몫**, 본 문서는
선택을 위한 자료.

## 현재 상태 (사실 기반)

### 데이터 모델 (`src/lib/puzzles.ts`)
- `category` enum: `principle | puzzle | alice` (3종)
- 옵셔널 `lessonGroup` 문자열로 *수업별 탐구* 서브그룹 분류
- 모든 카드는 `href` 자유 — URL과 카테고리는 *디커플링*
- 현재 `lessonGroup` 사용 카드는 **`linear_function`** 단 1개 (`'함수와 그래프'`)

### 라우팅
- 모든 퍼즐: `/puzzle/<id>` 경로 (디렉터리: `src/app/puzzle/<id>/`)
- 카테고리와 무관 — 예: `linear_function` 은 `category: 'principle'` 이지만 URL은 `/puzzle/linear-function`
- 즉 **URL은 `/puzzle/`로 평탄화**, 카테고리는 *목록 페이지에서만* 의미를 가짐

### 사이드바 (`src/components/Sidebar.tsx`)
4개 탑레벨 항목:
1. 🏠 HOME → `/`
2. 🧩 수학 퍼즐 → `/puzzles` (목록 + `/puzzle/*` 활성)
3. 📜 수학의 원리 → `/principles`
4. 💻 코딩의 원리 → `/coding`

### 목록 페이지 렌더링
- **`/puzzles`** — `category === 'puzzle'` 필터 (예상)
- **`/principles`** — `category === 'principle'` 카드를 *일반 원리 + lessonGroup별 섹션* 두 그룹으로 자동 렌더링. **새 lessonGroup 추가 시 코드 수정 없이 자동으로 섹션이 더 생김.**

### 결과: 신규 단원이 *현재 구조* 에서 어디에 위치하는가
- URL: `/puzzle/quadratic-function` 등 (linear-function과 동일 패턴)
- `category: 'principle'` (linear-function과 동일)
- `lessonGroup`: 미설정 시 일반 섹션, 설정 시 그룹 섹션

## 비교 옵션

### 옵션 A — 현행 유지 + 단일 lessonGroup
- 9단원 모두 `lessonGroup: '함수와 그래프'`
- linear-function 과 합쳐 10개 카드의 한 섹션
- **변경 사항**: 신규 단원 등록 시 `lessonGroup` 필드 추가뿐
- ✅ 가장 적은 작업, 0 코드 수정
- ❌ 10개 단원이 한 섹션에 몰려 *학습 순서·난이도* 가 평탄하게 보임 (이차함수와 적분이 같은 그룹에 나열)

### 옵션 B — lessonGroup 세분화 (추천)
3~4개 학습 흐름 그룹으로 세분:
| 그룹명 | 포함 단원 |
|--------|-----------|
| 함수의 종류 | 일차·이차·다항·지수와 로그 (단원 0,1,2,3) |
| 벡터 | 벡터 (단원 4) |
| 삼각함수 | 사인·코사인·탄젠트 (단원 5,6,7) |
| 미적분 | 미분·적분 (단원 8,9) |

- /principles 페이지가 **자동으로 4개 섹션** 으로 분리됨 (코드 수정 0)
- ✅ 학습 순서가 시각적으로 노출, 사용자가 *어디까지 왔는지* 한눈에
- ✅ 기존 렌더링 인프라 그대로 활용
- ❌ 벡터가 그룹당 1단원이라 외로움 (대안: '벡터'를 '함수의 종류'에 합치거나 '벡터·삼각함수'로 묶기)

### 옵션 C — 신규 카테고리 신설
- `category` 타입에 `'function'` 또는 `'calculus'` 추가
- 사이드바에 새 항목 *📈 함수와 미적분* → `/functions` 추가
- 새 목록 페이지 `/functions` 생성
- 디렉터리 이동(`/puzzle/...` → `/functions/...`) 은 **별개 결정** — URL 유지하면 작업 없음, 변경하면 9개 디렉터리 이동 + 리다이렉트
- ✅ 가장 또렷한 분리, 사이드바에서 즉시 접근
- ❌ 신규 페이지·신규 라우팅 구현 부담, 사이드바 4→5개 항목으로 밀집
- ❌ linear-function 의 거취도 결정 필요 (principle 에 둘지 옮길지)

### 옵션 D — `/principles` 하위 페이지 분리
- `/principles` 는 일반 원리만, `/principles/functions` 는 함수 9단원 전용
- 사이드바: *수학의 원리* 항목 그대로, 그 안에서 페이지 구성만 변경
- ✅ 사이드바는 그대로, URL은 의미를 더 정확히 반영
- ❌ 한 카테고리에 자식 페이지를 두는 패턴이 사이트에 없음 → 일관성 깨질 위험
- ❌ 사용자가 함수 단원에 도달하려면 클릭 한 번 추가

## 추천

**1순위: 옵션 B (lessonGroup 세분화)** — 코드 수정 0, 학습 흐름 또렷, 기존 인프라 100% 재활용.

**구체 그룹핑 제안 (옵션 B 채택 시)**:
- 그룹 1: **함수의 종류** — 일차·이차·다항·지수와 로그 (4단원)
- 그룹 2: **삼각함수** — 사인·코사인·탄젠트 + (벡터를 도입부로 합치는 안) (4단원)
- 그룹 3: **미적분** — 미분·적분 (2단원)

벡터는 *기하·삼각함수의 도구* 성격이 강하므로 그룹 2에 합치는 편이 깔끔. 단원 4 기획서를 보면 벡터는 *비행기 항로 = sin/cos 분해* 와 직결되어 매핑이 자연스럽다.

**2순위: 옵션 C (신규 카테고리)** — 사이트가 *함수·미적분* 영역으로 본격 확장한다는 시그널을 사용자에게 가장 강하게 전달. 작업량을 받아들일 수 있다면.
